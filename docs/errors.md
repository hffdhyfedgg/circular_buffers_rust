# ERRORS.md — Архитектура Системы Ошибок

Этот документ описывает строгие правила реализации обработки ошибок в крейтах рабочего пространства. Мы отказываемся от внешних зависимостей (включая `thiserror`) и реализуем систему вручную для полного контроля над размером бинарного файла и поведением в `no_std`.

---

## 1. Фундаментальные Принципы

1. **Локальность Ошибок:** Не существует общего крейта ошибок. Каждый крейт (`raw-storage`, `strided-mem`, `ring-buf`) определяет свой собственный `pub enum Error`.
2. **Стандартный Трейт:** Все типы ошибок обязаны реализовывать стандартные трейты ядра: `core::fmt::Debug`, `core::fmt::Display` и `core::error::Error`.
3. **Статический Размер:** Размер ошибки должен быть известен на этапе компиляции. Запрещено использовать `String`, `Box` или динамическое выделение памяти в типах ошибок.
4. **Отсутствие Паник в Релизе:** Безопасные методы не должны вызывать `panic!` в корректных сценариях использования. Паника допустима только в `debug_assert!` для нарушения логических инвариантов.

## 2. Стратегия «Статического Схлопывания» (Feature Flags)

Для оптимизации под микроконтроллеры (где важен каждый байт) и для отладки (где важен контекст) используется условная компиляция (`#[cfg]`).

### 2.1. Режимы сборки
В `Cargo.toml` каждого крейта объявляются флаги:
```toml
[features]
default = []
verbose-errors = []
```

### 2.2. Шаблон реализации ошибки
Каждый крейт обязан использовать следующий паттерн (пример для `ring-buf`):

```rust
use core::fmt;

// 1. Определение типа через условную компиляцию
#[cfg(feature = "verbose-errors")]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Error {
    /// Буфер переполнен при попытке записи
    BufferFull { index: usize, capacity: usize },
    /// Буфер пуст при попытке чтения
    BufferEmpty,
}

#[cfg(not(feature = "verbose-errors"))]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Error {
    /// Буфер переполнен
    BufferFull,
    /// Буфер пуст
    BufferEmpty,
}

// 2. Реализация Display (вручную)
impl fmt::Display for Error {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            #[cfg(feature = "verbose-errors")]
            Error::BufferFull { index, capacity } => {
                write!(f, "buffer overflow at index {} (capacity {})", index, capacity)
            }
            #[cfg(not(feature = "verbose-errors"))]
            Error::BufferFull => write!(f, "buffer overflow"),
            
            Error::BufferEmpty => write!(f, "buffer is empty"),
        }
    }
}

// 3. Реализация стандартного трейта ошибок
impl core::error::Error for Error {}

// 4. Локальный алиас результата для удобства
pub type Result<T> = core::result::Result<T, Error>;
```

## 3. Правила использования в коде

### 3.1. Безопасные методы
Методы, которые могут завершиться ошибкой (например, `push` в полный буфер без флага перезаписи), возвращают `Result<()>`.

### 3.2. Небезопасные методы (`_unchecked`)
Методы с суффиксом `_unchecked` (например, `push_unchecked`) **не возвращают ошибку**. Они предназначены для сценариев, где вызывающий код математически гарантировал отсутствие ошибки.
* Внутри таких методов разрешено использовать `#[allow(unsafe_code)]` и `core::hint::unreachable_unchecked()` для подсказки компилятору, что ошибочная ветка недостижима.
* Каждый такой блок обязан содержать комментарий `/// # Safety`, объясняющий, почему ошибка невозможна.

### 3.3. Запрет на аллокации
Запрещено хранить в ошибках строки или векторы. Максимум — целочисленные индексы (`usize`, `u32`), которые «схлопываются» в `cfg(not(verbose))`.

## 4. Чек-лист для ИИ-агента
При добавлении новой ошибки в крейт:
* [ ] Объявлен `enum` с атрибутами `#[cfg]` для `verbose-errors`.
* [ ] Реализован `fmt::Display` вручную для обеих конфигураций.
* [ ] Реализован `core::error::Error`.
* [ ] Создан `pub type Result<T>`.
* [ ] Ошибка не содержит типов с динамическим размером (`String`, `Vec`).
