# AGENTS.md

## Проект

Проект разрабатывается по SDD (Specification-Driven Development).
Принцип: ограничения → архитектурное решение → дельта-спецификация → кодогенерация.
Верификация: Creusot (предпочтительно всегда), тесты как дополнение.
Агент не принимает архитектурных решений во время реализации.

## Карта проекта

| Путь | Содержимое | Когда читать |
|---|---|---|
| `STATE.md` | Текущая задача, фаза, активные ограничения | Всегда, первым |
| `roles/` | Промпт вашей роли | По указанию в задаче |
| `spec/charter.md` | Устав проекта | Архитектор при старте |
| `spec/process.md` | Описание процесса | Архитектор при старте |
| `constraints/` | Ограничения, одно на файл (YAML) | Все роли, по необходимости |
| `delta_specs/` | Активные дельта-спецификации | Реализатор, рецензент |
| `templates/` | Шаблоны артефактов | Все роли |
| `reports/` | Отчёты по ролям | Рецензент, человек |
| `traces/` | Следы рецензента | Все роли, человек |
| `scripts/` | Скрипты создания артефактов | Все роли |

Каждая поддиректория содержит `archive/` для неактивных файлов.

## Создание артефактов

Не создавайте файлы вручную. Используйте скрипт:

```bash
scripts/new_artifact.sh <тип> <короткое-имя>
```

где `<тип>` ∈ {`delta_spec`, `arch_report`, `impl_report`, `rev_report`, `trace`}.
Скрипт копирует шаблон, присваивает следующий номер, выводит путь к файлу.
Заполняйте созданный файл содержимым.

## Жёсткие стоп-правила

Действуют для любой роли. Нарушение = остановка.

1. **Нет утверждённой дельта-спецификации → нет кода.**
   `status` дельты должен быть `approved` до начала реализации.

2. **Одна роль за проход.**
   Архитектор не пишет `impl`. Реализатор не меняет трейты и контракты.
   Рецензент не меняет код.

3. **Только человек утверждает.**
   Агент не ставит `status: approved` на дельты.
   Агент не редактирует и не удаляет файлы в `constraints/` без подтверждения человека.
   Агент не переносит файлы в `archive/` без указания человека.

4. **Не ослаблять ограничения.**
   Запрещено удалять, редактировать или обходить `constraints/*.yaml`
   без явного решения человека.

5. **При блокировке — стоп.**
   Если задача не может быть выполнена в рамках текущих данных:
   напишите `BLOCKED: <причина>` в отчёте и остановитесь.
   Не продолжайте, не «исправляйте по ходу».

## Эскалация к человеку

Обращайтесь к человеку, если:
- ограничения конфликтуют между собой;
- нужно изменить публичный трейт или контракт;
- нужно добавить зависимость;
- проверка не проходит после двух попыток;
- задача требует решения, не описанного в дельте.

Формат обращения:
```
Вариант A: ...
Вариант B: ...
Рекомендация: ...
Обоснование: ...
```

## Архив

Файлы в `archive/` не читаются и не учитываются при работе.
Перенос в `archive/` — только по явному указанию человека.
При переносе файл не удаляется и не редактируется.
